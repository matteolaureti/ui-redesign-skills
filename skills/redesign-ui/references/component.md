# Component redesign guidance

Use this guidance when the user wants to redesign one localized UI component or section rather than an entire product surface.

Examples include a card, table, modal, FAQ, pricing block, navigation element, settings panel, status widget, form, timeline, chart region, or dashboard module.

## Scope

Keep the redesign focused on the requested component. Show only enough surrounding interface to preserve context.

Do not invent a new application or redesign the whole page unless the user expands the scope.

## Preserve the job

Identify what the component needs to communicate and what actions it enables.

Preserve that job while allowing the component model itself to change. For example, a card can become a structured row, an accordion can become categorized Q&A, or a modal can become an expandable inline section when that better serves the task.

## Improve the micro-hierarchy

Use hierarchy, grouping, spacing, alignment, label/value relationships, status treatment, and action placement to make the component easier to understand.

Keep the result visually compatible with the surrounding product unless the user explicitly asks for a new global design direction.

## Avoid

Avoid cosmetic-only recolors, decorative mini charts, gratuitous gradients, excessive pills, icon-in-colored-square patterns, giant empty padding, or changing unrelated surrounding UI.

When generating multiple alternatives, vary information architecture or interaction presentation rather than only color, radius, or shadow.
