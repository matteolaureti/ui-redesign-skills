# iOS App Redesign

## Job to be done

Redesign an existing app screen so it feels intentionally designed for Apple's platforms rather than like a responsive website placed inside a phone.

Preserve the product task and meaningful content while improving:

- hierarchy;
- navigation;
- touch ergonomics;
- native conventions;
- platform coherence.

## Mandatory output rule

**ONE OUTPUT IMAGE = ONE iOS REDESIGN.**

Multiple concepts require separate image outputs.

Do not show several iPhone concepts in one image unless explicitly requested.

## Workflow

### 1. Identify device and context

Infer:

- iPhone or iPad;
- portrait or landscape;
- likely top-level destination;
- navigation depth;
- primary task;
- content type.

Do not assume iPhone patterns are always correct for iPad.

### 2. Respect safe areas

Keep important controls and content clear of:

- status regions;
- Dynamic Island / camera regions where relevant;
- home indicator;
- toolbars;
- tab bars;
- other system-reserved regions.

The concept should look implementable.

### 3. Design adaptively

Avoid layouts that depend on one exact fixed device width.

The visual structure should plausibly adapt to:

- larger text;
- different screen sizes;
- iPad/window layouts where relevant.

### 4. Account for Dynamic Type

Do not depend on tiny text.

Avoid brittle horizontal arrangements that would fail when text becomes larger.

Prefer layouts that can expand, wrap or stack gracefully.

### 5. Choose navigation intentionally

Use platform-familiar concepts when appropriate:

- navigation hierarchy;
- back navigation;
- top-level tabs;
- split navigation on larger devices;
- search;
- contextual destinations.

Do not invent desktop-like side navigation on iPhone without a strong reason.

### 6. Use tab bars for major destinations

A tab bar should represent meaningful top-level areas, not arbitrary actions.

Keep destination count controlled and labels understandable.

Do not use a tab bar merely because mobile apps often have one.

### 7. Keep toolbars focused

Toolbars should expose important contextual actions.

Avoid overcrowding.

Move lower-priority actions into an overflow/menu pattern when appropriate.

Use standard-feeling Back and Close behavior.

### 8. Use modality deliberately

Sheets, confirmation dialogs and full-screen modal experiences should serve a clear temporary task.

Do not use modal surfaces for ordinary navigation.

For focused editing, selection or multistep temporary work, a sheet or modal flow may be appropriate.

### 9. Prefer native-feeling controls

Use patterns that visually belong on iOS.

Avoid:

- desktop web dropdowns;
- tiny web checkboxes;
- hover-dependent interactions;
- dense desktop toolbars;
- web tables squeezed onto a phone;
- excessive boxed cards.

### 10. Optimize for touch

Important controls should:

- be visually tappable;
- have sufficient spacing;
- avoid cramped clusters;
- place repeated actions within reasonable reach.

### 11. Preserve content priority

Mobile redesign often requires progressive disclosure.

Decide what needs to be visible now and what can move into:

- drill-down;
- disclosure;
- sheet;
- detail view;
- secondary destination.

Do not delete useful information merely because the viewport is smaller.

### 12. iPad considerations

For iPad-like screenshots, consider:

- split views;
- sidebars where appropriate;
- larger content canvases;
- coexistence of navigation and contextual controls.

Avoid simply scaling an iPhone layout up.

## Visual language

The UI can retain the product's own brand while still feeling native.

Do not interpret “native iOS” as:

- making everything translucent;
- adding glass everywhere;
- copying Apple apps exactly;
- removing brand identity.

Native feeling comes from interaction and hierarchy conventions, not imitation alone.

## Common failure modes

Reject concepts that:

- look like a desktop dashboard compressed into a phone;
- ignore safe areas;
- use tiny text;
- use five different navigation systems;
- place too many toolbar actions;
- overuse sheets;
- use web-style form controls;
- make every content group a rounded card;
- put several redesign concepts into one image.

## Final checks

- Does the screen feel designed for iOS/iPadOS?
- Is the navigation model understandable?
- Are safe areas respected?
- Would larger text plausibly fit?
- Are toolbars restrained?
- Are tabs used only for meaningful destinations?
- Is modality purposeful?
- Are important controls touch-friendly?
- Is brand identity retained without fighting platform conventions?
- Does the output contain exactly one redesign?
