# Design Direction Explorer

## Job to be done

Explore the design space rather than repeatedly restyling one solution.

Use this skill when the user requests:

- several redesigns;
- multiple variants;
- different directions;
- alternative layouts;
- 4 / 6 / 8 concepts;
- experimentation.

## Non-negotiable output rule

**ONE OUTPUT IMAGE = ONE REDESIGN DIRECTION.**

If the user requests 8 redesigns:

- output 8 separate images;
- each image contains one complete concept;
- each concept receives the full canvas.

Never create:

- a 4x2 concept grid;
- a contact sheet;
- eight miniature browser windows;
- a moodboard of UI variants;
- side-by-side redesigns;
- before/after layouts;

unless that format was explicitly requested.

## The diversity requirement

Multiple concepts must differ in major design decisions.

A concept is not meaningfully different if only these change:

- color;
- border radius;
- shadows;
- font;
- illustration;
- accent color.

Each concept should change several of:

- global composition;
- navigation;
- hierarchy;
- density;
- grouping;
- component model;
- primary focal point;
- information flow;
- visual rhythm;
- use of imagery;
- content disclosure.

## Workflow

### 1. Define invariants

Before exploring, establish what all concepts must preserve:

- product purpose;
- core functionality;
- required content;
- brand constraints;
- device category;
- any user-specified restrictions.

These remain stable.

### 2. Define design axes

Select useful axes for variation.

Examples:

#### Composition

- traditional;
- asymmetric;
- split;
- master-detail;
- full-width workspace;
- contextual side rail.

#### Density

- compact;
- balanced;
- spacious.

#### Navigation

- sidebar;
- compact rail;
- top navigation;
- contextual tabs;
- hierarchical navigation.

#### Visual emphasis

- data-first;
- content-first;
- image-led;
- typography-led;
- task-first;
- anomaly-first.

#### Component language

- integrated surfaces;
- structured rows;
- minimal containers;
- modular panels;
- table-centric;
- editorial sections.

### 3. Allocate distinct directions

For eight requested concepts, a useful default exploration set is:

1. **Conservative evolution**  
   Familiar structure, dramatically improved execution.

2. **Structural rethink**  
   Same product meaning with a new global composition.

3. **Dense professional**  
   Power-user efficiency and high information density.

4. **Minimal product**  
   Reduced chrome and fewer explicit containers.

5. **Editorial**  
   Stronger type, asymmetry and deliberate visual rhythm.

6. **Command center**  
   Current state, monitoring and actions dominate.

7. **Contextual workspace**  
   UI organized around the selected entity or task.

8. **Brand-forward**  
   Product identity becomes more distinctive without sacrificing usability.

Do not mechanically use these eight if the product suggests better directions.

### 4. Prevent concept convergence

Before each new output, compare its design decisions to prior concepts.

If it reuses the same:

- page skeleton;
- card grid;
- navigation architecture;
- focal point;

change the structure before generating.

### 5. Maintain quality across concepts

Diversity is not an excuse for random experimentation.

Every concept must still be:

- usable;
- coherent;
- realistic;
- appropriate to the product;
- visually deliberate.

## Output behavior

Do not write “Concept 1”, “Concept 2” inside the generated UI unless such labels are part of the product.

The image should look like the product itself, not a presentation board.

Each redesign should be shown at a useful scale.

## Final checks for each concept

- Exactly one redesign in this image?
- Structurally different from prior outputs?
- Same product purpose preserved?
- Important functionality retained?
- Realistic enough to ship?
- Distinct for reasons deeper than color?
- Full canvas used for this concept?

If any answer is no, revise the concept before finalizing.
